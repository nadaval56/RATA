# התאמת אתר לחוק הישראלי — פרטיות ונגישות

הערכה הזו מכסה שני חוקים שונים שנפגשים באותם קבצים:

- **פרטיות** — חוק הגנת הפרטיות, התשמ"א‑1981, לאחר **תיקון מס' 13**
  (התשפ"ה‑2024, בתוקף מ‑14.8.2025). החובה המרכזית לאתר תוכן היא
  **חובת היידוע** שבסעיף 11.
- **נגישות** — **תקנה 35** לתקנות שוויון זכויות לאנשים עם מוגבלות
  (התאמות נגישות לשירות), התשע"ג‑2013, שמפנה ל**ת"י 5568** (מבוסס
  `WCAG 2.0`) ברמת התאמה **AA**.

הפירוט המשפטי, כולל מה מאומת ומה לא — `references/israeli-law.md`.

## הכלל שקובע הכול: קודם לברר, אחר כך לכתוב

מדיניות פרטיות היא **תיאור עובדתי** של מה שהאתר עושה. מדיניות שנכתבה
מתבנית ולא מבדיקה היא, במקרה הרע, הצהרה כוזבת. לכן הצעד הראשון תמיד
הוא ביקורת, ורק אחריה כתיבה.

```bash
# כל כתובת חיצונית בקוד — כל אחת מהן היא צד שלישי שצריך להיות במדיניות
grep -rnoE 'https?://[a-zA-Z0-9./_-]+' --include=*.html --include=*.js --include=*.css . \
  | grep -v "$(cat CNAME 2>/dev/null || echo YOUR_DOMAIN)"

# כלי מדידה, עוגיות, אחסון מקומי
grep -rniE 'gtag|googletagmanager|analytics|fbq|facebook\.net|hotjar|clarity|matomo|plausible|segment|intercom|document\.cookie|localStorage|sessionStorage|indexedDB' \
  --include=*.html --include=*.js .

# פונטים מרוחקים (בקשה לגוגל בכל טעינת דף)
grep -rn 'fonts.googleapis\|fonts.gstatic\|use.typekit' --include=*.html --include=*.css .

# טפסים ונקודות קליטה
grep -rn '<form\|<input\|fetch(\|XMLHttpRequest\|navigator.sendBeacon' --include=*.html --include=*.js .
```

הממצאים קובעים איזו מדיניות נכתבת:

| מה נמצא | מה זה אומר |
|---|---|
| אין כלום | "האתר אינו אוסף מידע" — הצהרה חזקה, ומותר לכתוב אותה רק אם בדקת |
| `localStorage` בלבד | מידע שנשאר במכשיר. פרט כל מפתח בטבלה, ותן שליטה אמיתית |
| Analytics / פיקסל | יש איסוף. נדרשת הסכמה **לפני** ההפעלה, לא באנר שמודיע בדיעבד |
| טופס | פרט אילו שדות, לאן הם נשלחים, כמה זמן נשמרים ומי ניגש |
| פונטים מרוחקים | כתובת ה‑IP של הגולש מגיעה לספק הפונטים. עדיף להוריד ולהגיש מקומית |

**גם באתר סטטי לחלוטין יש שני דברים לחשוף בגלוי**, ורוב המדיניות שוכחות אותם:
יומני השרת של ספק האחסון (IP + `User-Agent`, נרשמים תמיד), וכלים כמו
Google Search Console. שים לב לדיוק: Search Console **אינו** מתקין קוד
ואינו כותב עוגייה — האימות הוא קובץ טקסט סטטי, והנתונים מגיעים ממערכות
גוגל ולא מהאתר. אל תתאר אותו כאילו הוא Analytics.

## מהלך העבודה

### 1. ביקורת פתיחה

הרץ את הביקורת האוטומטית לפני שנגעת בקוד — היא נותנת את רשימת המשימות:

```bash
npm i -D playwright          # אם עדיין לא מותקן
node scripts/audit.mjs --root .
```

הסקריפט בודק שישה דברים ומדפיס דוח מפורט עם `file:line`:
גדלי גופן ב‑`px`, הגדלה בפועל, מטריצת פקדי הנגישות, גלישה אופקית
ב‑320px, מבנה סמנטי, וניגודיות מול הרקע האפקטיבי. קוד יציאה 1 אם
נמצאה בעיה, כך שאפשר לחבר אותו ל‑CI.

לבדיקת פלטה נפרדת: `python3 scripts/contrast.py --css path/to/style.css`
— הוא גם מציע גוון חלופי לכל כשל, תוך שמירה על הגוון המקורי.

יש `px` שנשאר `px` בכוונה — פקד שאמור להישאר יציב בכל המדרגות, כמו סרגל
בחירת הגודל עצמו. סמן אותו בהערה `/* a11y-allow-px */` באותה שורה
והביקורת תדלג עליו. במדידה החיה, פקדים שנושאים `data-fs` (סרגל בחירת
הגודל עצמו) או `data-a11y-allow-px` מוחרגים באותו אופן. חריג מוצהר
עדיף על בדיקה שמתרגלים להתעלם ממנה.

### 2. שתילת הרכיבים

העתק מ‑`assets/`: `a11y.css`, `a11y.js`, `privacy.js`. הם עצמאיים —
אין תלות בספרייה, במסגרת עבודה או בשרת, והם עובדים גם אופליין.

בכל דף, ב‑`<head>` אחרי גיליון הסגנון של האתר:

```html
<link rel="stylesheet" href="/assets/css/a11y.css">
<!-- החלה מוקדמת של ההעדפות, לפני הציור הראשון — אחרת יש הבהוב -->
<script>
try{
  var _p=localStorage.getItem('privacy:v1');
  if(!_p||JSON.parse(_p).local!==false){
    var _r=document.documentElement,_a=localStorage.getItem('a11y:v1');
    if(_a){_a=JSON.parse(_a);
      if(_a.fs)_r.setAttribute('data-fs',_a.fs);
      if(_a.mode)_r.classList.add('a11y-'+_a.mode);
      ['links','readable','spacing','still','cursor','focus']
        .forEach(function(k){if(_a[k])_r.classList.add('a11y-'+k);});}
  }
}catch(e){}
</script>
```

ולפני `</body>` — **privacy.js תמיד ראשון**, כי a11y.js וקוד האחסון של
האתר שואלים אותו אם מותר לכתוב:

```html
<script src="/assets/js/privacy.js"></script>
<script src="/assets/js/a11y.js"></script>
```

התאמה אופציונלית, לפני הסקריפטים:

```html
<script>
window.PRIVACY_CONFIG = { appPrefixes:['myapp:','a11y:'] };  // מפתחות שהאתר שומר
window.A11Y_CONFIG    = { privacyUrl:'/privacy/', accessibilityUrl:'/accessibility/',
                          dockSelector:'.my-bottom-bar' };   // סרגל תחתון קבוע, אם יש
</script>
```

אם לאתר יש קוד שכותב ל‑`localStorage`, נתב אותו דרך `PRIVACY.get/set` —
אחרת הבחירה "בלי שמירה מקומית" תהיה הצהרה ריקה.

### 3. שני המסמכים

`assets/privacy-template.html` ו‑`assets/accessibility-template.html`.
החלף כל `{{...}}`; הרשימה המלאה בראש כל קובץ.

**שני פרטים חייבים להגיע מהמשתמש — אל תמציא אותם:** שם מפעיל האתר,
וכתובת ליצירת קשר. הצהרת נגישות בלי פרטי רכז נגישות אינה עומדת בתקנה 35.

מה שהופך את המסמכים האלה לטובים מהתבניות שברשת:

- **פקדים חיים** בדף הפרטיות — עיון במה ששמור, ייצוא ומחיקה, בדפדפן
  ובלי טופס פנייה. זכות העיון שבסעיף 13 ממומשת בכפתור, לא בהבטחה.
- **מגבלות ידועות** בהצהרת הנגישות. הצהרה שמפרטת מה עדיין לא מושלם
  אמינה יותר מהצהרה שמכריזה על שלמות, וגם מגינה טוב יותר.
- **אמירה מפורשת** אם לא נערכה ביקורת של מורשה נגישות מוסמך.
- ציון הפטור, אם רלוונטי — ראה `references/israeli-law.md`.

### 4. תיקון הכשלים בקוד עצמו

זה החלק שקובע לפי התקן. תפריט נגישות **אינו מנגיש אתר**; הוא מוסיף
התאמות תצוגה מעל אתר שכבר נגיש. `references/pitfalls.md` מרכז את
התקלות שחוזרות — קרא אותו לפני שאתה מתקן, הוא יחסוך לך סבב.

### 5. אימות

הרץ שוב את `audit.mjs` עד קוד יציאה 0. אם לאתר יש Service Worker —
העלה את גרסת הקאש, אחרת התקנות קיימות ימשיכו להגיש את הקוד הישן.

## מה לא לעשות

**אל תשתמש בתוסף נגישות מסחרי.** שלוש סיבות, לפי סדר החומרה:

1. תפריט אינו מנגיש אתר. ת"י 5568 דורש נגישות בקוד — סמנטיקה, ניווט
   מקלדת, ניגודיות, תיאורים. תוסף צף לא נותן אף אחד מהם, ויוצר מראית
   עין של עמידה בדרישה.
2. הוא סקריפט שנטען מדומיין אחר ורץ בדף. הוא סותר כל מדיניות פרטיות
   שמבטיחה "אין צד שלישי" — כלומר את המסמך שכתבת באותו יום.
3. הוא לא עובד אופליין, מה שמבטל אותו ב‑PWA.

**אל תצטט סעיף חוק שלא אימתת.** אם אין גישה למקור, נסח כללית
("התקנות קובעות פטורים לפי מחזור והיקף שירות") במקום להמציא מספר
סעיף או סכום. `references/israeli-law.md` מסמן במפורש מה מאומת.

**אל תבדוק שתכונה נקבעה — בדוק שמשהו קרה.** בדיקה שמוודאת שהתכונה
`data-fs` נכתבה עוברת בהצלחה על אתר שבו שום דבר לא גדל. מדוד
`getComputedStyle` לפני ואחרי. זו טעות שכבר עלתה סבב שלם.

**אל תספור הצלחות בלי לספור כישלונות.** `grep -c PASS` על חבילה
של 15 בדיקות יחזיר 14 בלי לרמוז שאחת נכשלה.
